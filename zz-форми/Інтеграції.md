# Інтеграції

!!! Для чого потрібна програма Checkbox KasaManager? Чи є технічні вимоги до ОС?
Checkbox Kasa Manager - графічний інтерфейс управління консольною утилітою Checkbox Kasa, яка генерує і фіскалізує чеки в ДПС. Він встановлюється на касовий вузол на ПК і обирається у фронт-системі як касовий апарат.
Для версій Windows: 7 SP1, 8, 8.1, 10, 11, Server 2008, 2012, 2016, 2019
Оперативна пам'ять: мінімум 1 ГБ, вільне місце на диску від 1 ГБ
Роздільна здатність екрана: мінімум 1024х768 px
Для OS Windows: встановлений NET.Framework4.2

!!! Що таке фронт-система?
Програмне забезпечення (інтерфейс), через яке касир здійснює реальні продажі: формує чеки, проводить оплати та видає їх покупцеві, взаємодіючи з ядром пРРО Checkbox. Вона встановлюється на ПК, планшет або працює через веб-інтерфейс, надсилаючи дані до ДПС.
Функціонал: Дозволяє відкривати/закривати зміну, продавати товари, робити повернення та формувати X/Z-звіти.
Інтеграція: Фронт-система може працювати як самостійна програма або бути інтегрована в облікову систему (наприклад, 1С/BAS, POS-системи) через API.
Checkbox Kasa Manager: Спеціальний застосунок для налаштування та управління касами, що працює в фоновому режимі.
Віддалений сервер: Можливість налаштування, при якій фронт-система підключається до віддаленого сервера.
Фронт-система забезпечує роботу касира, а сервер Checkbox забезпечує юридичну фіскалізацію цих дій.

!!! Що таке пін-код касира? Хто його генерує, ми чи ДПС? \*
Пін-код (пароль) касира в Checkbox — це персональний код безпеки, який використовується для входу в касовий додаток та ідентифікації касира при підписанні чеків. Його генерує та встановлює сам користувач (адміністратор або касир) в особистому кабінеті Checkbox, а не ДПС.
Пін-код — це пароль доступу до сервісу Checkbox, а не податковий номер.

!!! Що таке ключ ліцензії каси?
Хто його генерує, ми чи ДПС? \*
Ключ ліцензії (або ключ касира/печатки) у Checkbox — це КЕП (кваліфікований електронний підпис), який використовується для автоматичного підписання чеків і реєстрації їх у ДПС. Генерує його не Checkbox, а ДПС (або інший акредитований ЦСК), наприклад, ПриватБанк, а Checkbox лише використовує його для автоматизації.

!!! До яких фронт-систем можна підключати Checkbox Касу? Напишіть 5 таких систем. \*
До Checkbox можна підключити сотні різних систем, оскільки це хмарний сервіс з відкритим API.
Poster — одна з найпопулярніших систем автоматизації для кафе та ресторанів.
Bas (раніше 1С) — класичне рішення для бухгалтерського та складського обліку.
KeyCRM — CRM-система для товарного бізнесу та послуг, де чеки створюються прямо в картці замовлення.
Rozetka — Checkbox інтегрується безпосередньо в кабінет продавця для автоматичної видачі чеків покупцям.
PrestaShop — популярний двіжок для інтернет-магазинів (аналогічно є модулі для WordPress/WooCommerce, OpenCart та Shopify).

!!! Який протокол емулює Checkbox Kasa Manager? \*
Checkbox Kasa Manager найчастіше емулює протокол фізичних касових апаратів «Марія 304» (через TCP-порт, зазвичай 13000 або наступні). Цей режим дозволяє інтегрувати програмний РРО з обліковими системами (наприклад, 1С/BAS), які раніше працювали з фіскальними реєстраторами.

!!! Чи може працювати клієнт з Checkbox Kasa без інтернету чи зв'язку із сервером checkbox? \*
Так, програмна каса Checkbox Kasa може працювати без інтернету або зв'язку із сервером ДПС в офлайн-режимі. Вона використовує заздалегідь отримані офлайн-коди (2000 шт.) для фіскалізації чеків, автоматично синхронізуючи дані з податковою, коли зв'язок відновлюється.

!!! Чи обов’язково переносити товари на портал Checkbox, якщо я маю свою програму обліку, з якою буду працювати? \*
Ні, переносити товари на портал Checkbox необов'язково, якщо використовується власна облікова система (1С, BAS, Poster, Хорошоп тощо) з інтеграцією через API. Чекбокс виступає лише інструментом для фіскалізації (передачі даних до ДПС), а номенклатура, ціни та звіти формуються у власній системі.

!!! Чи можна відкрити зміну через Checkbox Каса, а закрити через портал? \*
Так, можна відкрити зміну через застосунок Checkbox.Каса, а закрити її через особистий кабінет (портал). Цей метод, відомий як «аварійне закриття», використовується, якщо локальна каса не може закрити зміну через офлайн-режим або технічні помилки.
Важливі нюанси:
Ризик помилок: Не рекомендується постійно змішувати способи закриття (API/Портал vs Каса), оскільки це може призвести до розбіжностей у звітах.
Офлайн-режим: Якщо зміну закрити через портал, а на самій касі залишилися невідправлені чеки, потрібно обов'язково зробити Z-звіт на касі, коли з'явиться зв'язок.
Алгоритм аварійного закриття: В особистому кабінеті (порталі) перейдіть у розділ «Каси», оберіть потрібну касу, натисніть «...» та «Аварійне закриття зміни».

!!! Що таке Аварійне закриття зміни? У яких випадках воно потрібне? \*
Якщо Ви користуєтесь Checkbox.Каса і у випадку вимикання світла, а вам терміново потрібно закрити зміну - ви можете скористатись функціоналом Аварійного закриття зміни.

!!! Я маю самописний інтернет магазин, як мені фіскалізувати продажі? Яку інформацію можемо надати клієнту? \*
Для фіскалізації самописного інтернет-магазину через Checkbox (ПРРО) інтегруйте Checkbox API з вашою базою даних. Це дозволяє автоматично створювати чеки після оплати. Клієнту ви надаєте електронний фіскальний чек (посилання або PDF) у Viber/Telegram/Email, який підтверджує легальність покупки.
Як фіскалізувати самописний магазин з Checkbox.
Зареєструйтеся на сайті my.checkbox.ua, додайте торгову точку (адресу), касу та касира (потрібен ЕЦП).
Використовуйте документацію Checkbox API для підключення вашої CMS. Коли система отримує підтвердження оплати (liqpay, monobank тощо), вона має надіслати запит на створення чека.
Налаштуйте автоматичне закриття зміни (Z-звіт) щодня та відкриття нової, щоб не робити це вручну.
Кожна оплата автоматично фіскалізується: чек формується в податковій та повертається у вашу систему.

!!! Що таке Checkbox Paylink? В чому різниця з AirCheck by checkbox?
Checkbox Paylink
Це рішення для підключення класичного (стаціонарного) POS-терміналу до каси
Як це працює: Ви з'єднуєте свій звичайний банківський термінал із комп’ютером або планшетом, де встановлено ПРРО.
Основна перевага: Коли ви створюєте чек у Checkbox, сума автоматично передається на термінал. Клієнту не потрібно вводити суму вручну, а дані про оплату (ЕПЗ) автоматично потрапляють у фіскальний чек.
Кому підходить: Магазинам або закладам, які вже мають окремий банківський термінал і хочуть синхронізувати його з касою.
AirCheck by Checkbox
Це інтеграція для сучасних Android POS-терміналів (так званих пристроїв «3в1») або смартфонів. Раніше цей сервіс мав назву «Суперкаса».
Як це працює: ПРРО та банківський термінал працюють в межах одного пристрою або тісно інтегрованого додатка на Android.
Основна перевага: Повна синхронізація еквайрингу та каси на одному девайсі. Це дозволяє уникнути помилок при введенні суми та спрощує роботу бухгалтера, оскільки звіти з терміналу та ПРРО завжди збігаються.
Кому підходить: Мобільним точкам продажу, кур'єрам або бізнесу, який хоче мати компактне рішення «каса + термінал» в одному гаджеті.

!!! Клієнт хоче підключити термінал до інтеграції Cliniccards. Що в даному випадку порадити клієнту, підключення за допомогою AIRCHECK чи Checkbox Paylink? \*
Для інтеграції терміналу з Cliniccards, найкращим варіантом є використання Checkbox Paylink. Paylink автоматизує передачу суми з Cliniccards на термінал та автоматично фіксує оплату в ПРРО, виключаючи людські помилки при введенні суми.
Чому радять Paylink (а не AIRCHECK):
Повна автоматизація: Клієнт натискає "Оплатити" в Cliniccards, сума одразу з'являється на терміналі Paylink.
Інтеграція з ПРРО: Після успішної оплати чек автоматично фіскалізується через Checkbox, а статус в Cliniccards змінюється на "Оплачено" Paylink.
Швидкість: Менше дій для адміністратора, вища швидкість обслуговування пацієнтів.
Налаштувати Paylink через розділ "Еквайринг" у Checkbox, дотримуючись інструкції Cliniccards.

!!! Що таке API?
Це програмний інтерфейс (RESTful API), що дозволяє автоматично фіскалізувати розрахункові операції, інтегруючи сервіс пРРО Checkbox у вебсайти, CRM, ERP-системи або мобільні додатки. Він автоматично реєструє чеки в ДПС, підписує їх хмарним КЕП та відправляє покупцям, замінюючи фізичні касові апарати.
Набір інструкцій, який дозволяє одній програмі "спілкуватися" з іншою.
Назвіть кілька АРІ інтеграцій
CRM-системи: Повна інтеграція з KeyCRM та SITNIKS для автоматичного створення, відправки чеків у месенджери та закриття змін.
Облікові системи (ERP): Модулі для BAS/1C та Odoo, що забезпечують обмін даними в реальному часі.
Електронна комерція (CMS): Інтеграція з платформами інтернет-магазинів (наприклад, через API для індивідуальних рішень).
Платіжні сервіси: Автоматичне створення чека при отриманні оплати.
API-конектори: ApiX-Drive дозволяє налаштувати зв'язок Checkbox з іншими системами.

!!! У клієнта вединговий апарат (Кавомашина самообслуговування), у архіві чеків є чеки повернення, на чиїй стороні потрібно робити перевірку? На нашій чи стороні інтегратора? Чому? \*
Перевірку потрібно робити насамперед на стороні інтегратора (розробника ПЗ, яке керує кавомашиною).
Ось чому:
Checkbox — це виконавець: Сервіс лише фіскалізує ті дані, які йому надсилає ПЗ кавомашини. Якщо в архіві є чеки повернення, це означає, що кавомашина сама ініціювала команду на створення такого чека.
Логіка операцій: Тільки інтегратор знає, за яких умов формується запит до Checkbox. Можливо, стався технічний збій (не випав стакан, не налилася кава) або налаштовано автоматичне повернення при скасуванні замовлення користувачем.
Логи запитів: Інтегратор може перевірити свої внутрішні логи: чи був надісланий запит на POST /api/v1/receipts/sell (продаж) чи на POST /api/v1/receipts/return (повернення).
Checkbox варто залучати лише тоді, коли інтегратор впевнений, що надсилав запит на продаж, а сервіс чомусь видав чек повернення (що технічно майже неможливо без відповідної команди).

!!! Які умови потрібно виконати, щоб використовувати інтеграцію з Новою Поштою? Опишіть алгоритм підключення, та роботи. \*
Наявність акаунту в Checkbox: Зареєстрований кабінет продавця.
Діючий ПРРО: Відкрита каса (каса/зміна) у Checkbox.
Акаунт Нової Пошти (Бизнес-кабінет): Отриманий API-ключ для доступу до сервісів Нової Пошти.
Використання післясплати: Інтеграція орієнтована на автоматизацію чеків саме при оплаті при отриманні.
Алгоритм підключення
Авторизація: Увійдіть у особистий кабінет Checkbox.
Налаштування інтеграції: Перейдіть у розділ «Інтеграції» -> «Нова Пошта».
Введення API-ключа: Вкажіть API-ключ, отриманий у бізнес-кабінеті Нової Пошти.
Вибір каси: Виберіть касу (ПРРО), через яку будуть проходити фіскальні чеки.
Перейдіть в бізнес кабінет Нової Пошти (як ФОП/Юр. особа) → оберіть розділ “Налаштування” → далі підрозділ “Безпека” та згенеруйте ключ API для інтеграцій.
Скопіюйте створений ключ.
На сайті Checkbox перейдіть у розділ Каси та оберіть касу, яку ви хочете використовувати для інтеграції.
Навпроти вашої каси натисніть в колонці “ДІЇ” натисніть “···” → оберіть “Додати токен Нова Пошта” → вставте раніше створений/скопійований токен API та натисніть Зберегти.

!!!Чи можна відкрити зміну через мобільний застосунок, а закрити через портал?
Так, відкрити касову зміну (ПРРО) через мобільний застосунок, а закрити через вебпортал (особистий кабінет) можна. ПРРО працює за принципом синхронізації, тому зміна, відкрита на одному пристрої, вважається активною для каси загалом і може бути закрита через інший інтерфейс.

!!!Чи є можливість замінити ключ касиру у мобільному застосунку?
Так, заміна ключа касира (ЕЦП/КЕП) у мобільних застосунках пРРО (наприклад, Checkbox, WayForPay) можлива. Зазвичай це робиться через розділ «Касири» або «Налаштування пРРО», де обирається дія «Заміна ключа» або «Оновити ключ». Попередньо потрібно отримати новий ключ у ДПС та зареєструвати.
